<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Domain Models → SQLite Storage | User inputs (customer snapshot, cassette text, payment method, tracking code, photo file IDs) stored into SQLite orders table |
| Telegram Client → Bot Polling | Ping and start commands invoked by authenticated Telegram users |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-08 | Tampering | `src/db/orders.py` | mitigate | Parameterized SQL queries prevent injection via order text or tracking codes |
| T-01-09 | Tampering | `src/db/schema.py` | mitigate | `CHECK (status IN (...))` constraint enforces valid status values directly at the database engine level |
| T-01-10 | Repudiation | `src/db/orders.py` | mitigate | Snapshot fields (`customer_name`, `customer_phone`, `shipping_address`) ensure historical orders remain unaltered even if customer record changes |
| T-01-11 | Denial of Service | `src/bot/handlers/base.py` | mitigate | `/ping` DB check uses lightweight `SELECT 1` with 5s timeout to avoid tying up worker threads |
| T-01-SC | Tampering | Dependency packages | mitigate | Standard stack verified via package legitimacy audit in RESEARCH.md |
</threat_model>
