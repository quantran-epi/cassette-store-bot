<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Telegram upload -> bot filesystem | File do admin tải lên là input không tin cậy (sai định dạng, gzip bomb, SQLite độc hại) |
| Staged file -> live DB | Ghi đè DB đang phục vụ; lỗi giữa chừng có thể mất dữ liệu |
| Callback `adm:rst:*` | Bất kỳ ai bấm nút; phải kiểm tra role + đúng người đã upload |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-261027-01 | Tampering | `stage_restore_archive` | mitigate | Kiểm tra magic bytes `SQLite format 3\0`, `PRAGMA integrity_check` phải trả `ok`, xác minh bảng/cột bắt buộc qua `PRAGMA table_info`, mở staged DB bằng URI `mode=ro` |
| T-261027-02 | Denial of Service | giải nén gzip | mitigate | Stream giải nén theo chunk, dừng và raise khi vượt `MAX_RESTORE_UNCOMPRESSED` (256 MB); từ chối `document.file_size > 20 MB` trước khi tải |
| T-261027-03 | Tampering | `apply_staged_restore` | mitigate | `VACUUM INTO backups/pre_restore_<ts>.sqlite3` làm snapshot an toàn trước khi `source.backup(dest)`; `busy_timeout=5000`; checkpoint sau khi ghi |
| T-261027-04 | Elevation of Privilege | `handle_backup_document`, `handle_restore_callback` | mitigate | `@require_role(UserRole.SUPER_ADMIN)`; callback kiểm tra `pending["user_id"] == update.effective_user.id` |
| T-261027-05 | Information Disclosure | staging dir | mitigate | Dùng `tempfile.mkdtemp(prefix="restore_")`, tên file cố định `upload.gz`/`restore.sqlite3`, không dùng `document.file_name` làm path; `shutil.rmtree` trong `finally` mọi nhánh |
| T-261027-06 | Tampering | temporary file leftovers | accept | Bot restart giữa upload và xác nhận có thể để lại thư mục trong OS temp; dọn thư mục `restore_*` cũ hơn 1 giờ ở mỗi lần upload mới |
</threat_model>

Mở rộng `src/services/backup.py` (giữ nguyên API xuất backup hiện có):

1. Thêm `class RestoreValidationError(ValueError)`.
2. Thêm hằng `MAX_RESTORE_UNCOMPRESSED = 256 * 1024 * 1024` và dict bảng/cột bắt buộc tối thiểu: `customers` → `id, name, phones, addresses`; `orders` → `id, customer_name, customer_phone, shipping_address, items_text, total_amount, cod_amount, payment_method, status`. (Cột mới như `tapes_json` do `init_db` bù sau, không chặn backup cũ.)
3. `def stage_restore_archive(gz_path: str, staging_dir: str) -> dict` (đồng bộ, gọi qua `to_thread` từ handler):
   - `os.makedirs(staging_dir, exist_ok=True)`, staged path `os.path.join(staging_dir, "restore.sqlite3")`.
   - Mở gzip (`gzip.open`); bọc `BadGzipFile`/`OSError`/`EOFError` thành `RestoreValidationError("File không phải định dạng gzip hợp lệ")`.
   - Đọc theo chunk 1 MB, ghi ra staged, cộng dồn; nếu vượt `MAX_RESTORE_UNCOMPRESSED` → xoá staged, raise lỗi rõ ràng.
   - Kiểm tra 16 byte đầu == `b"SQLite format 3\x00"`.
   - Mở `sqlite3.connect(f"file:{staged}?mode=ro", uri=True)`; `PRAGMA integrity_check` phải trả đúng `[("ok",)]`; đọc `PRAGMA table_info(...)` cho từng bảng bắt buộc, thiếu bảng/cột → raise; đếm `SELECT COUNT(*) FROM orders/customers`.
   - `finally`: đóng connection; mọi exception đều `os.remove(staged)` nếu tồn tại.
   - Trả `{"staged_path", "raw_size", "order_count", "customer_count"}`.
4. `def apply_staged_restore(staged_path: str, db_path: str, backup_dir: str = "backups") -> dict` (đồng bộ, chạy trong `to_thread`):
   - `os.makedirs(backup_dir, exist_ok=True)`; safety path `pre_restore_<YYYYmmdd_HHMMSS>.sqlite3` (UTC+7 như `execute_backup`).
   - Mở `dest = sqlite3.connect(db_path)`; `dest.execute("PRAGMA busy_timeout = 5000")`; `dest.execute("VACUUM INTO ?", (safety_path,))` — snapshot DB hiện tại trước khi thay.
   - Mở `source = sqlite3.connect(f"file:{staged}?mode=ro", uri=True)`; `source.backup(dest)`.
   - `dest.execute("PRAGMA wal_checkpoint(TRUNCATE)")`; commit/close cả hai trong `finally`.
   - Trả `{"safety_path": safety_path}`.
5. Đặt `ponytail:` comment ở `apply_staged_restore`: restore chạy trong lúc bot polling; handler phải tránh thao tác ghi đồng thời (busy_timeout + backup API đủ cho quy mô shop nhỏ). Nâng cấp: dừng polling/lock toàn cục nếu cần zero-downtime.
