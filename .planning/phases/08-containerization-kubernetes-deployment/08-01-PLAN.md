# Plan 08-01: Runtime Daemon Hardening (Healthcheck Probe & Post-Shutdown WAL Checkpoint)

<objective>
Implement the container runtime healthcheck probe script (`src/scripts/healthcheck.py`) using only Python standard library, configure the periodic 30s heartbeat JobQueue task in `src/bot/app.py`, and implement the `ApplicationBuilder.post_shutdown` hook to execute `PRAGMA wal_checkpoint(TRUNCATE)` for clean database shutdown on SIGTERM/SIGINT.
</objective>

<threat_model>
- **Threat Ref:** T-08-03 (Denial of Service / Stalled Daemon Event Loop)
- **STRIDE:** Denial of Service
- **Impact:** Bot process stops processing Telegram updates while staying alive, leading to lost customer orders.
- **Mitigation:** Independent JobQueue background task writes timestamp to `/tmp/bot_heartbeat` every 30s. Probe script tests heartbeat file freshness (<90s) and runs SQLite ping (`SELECT 1` with 2.0s timeout). Exits 0 on healthy, 1 on unhealthy.
- **Threat Ref:** T-08-04 (SQLite Journal Corruption on Pod Termination)
- **STRIDE:** Tampering
- **Impact:** Unflushed WAL pages cause recovery stalls or corrupted `-wal`/`-shm` state when container moves across nodes.
- **Mitigation:** PTB `post_shutdown` executes `PRAGMA wal_checkpoint(TRUNCATE)` to flush all pages to main DB and resize WAL to 0 bytes before closing connection.
</threat_model>

<task id="08-01-02">
  <name>Implement zero-dependency healthcheck probe script</name>
  <read_first>
    - src/config.py

    - .planning/phases/08-containerization-kubernetes-deployment/08-PATTERNS.md
  </read_first>
  <action>
    1. Create `src/scripts/__init__.py`.
    2. Create `src/scripts/healthcheck.py` using ONLY Python standard library (`os`, `sqlite3`, `sys`, `time`):
       - `HEARTBEAT_FILE = "/tmp/bot_heartbeat"`
       - `MAX_HEARTBEAT_AGE = 90` (seconds)
       - `DB_PING_TIMEOUT = 2.0` (seconds)
       - `check_heartbeat()`: Verifies file existence and `time.time() - os.path.getmtime(HEARTBEAT_FILE) <= MAX_HEARTBEAT_AGE`.
       - `check_database()`: Reads `os.environ.get("SQLITE_DB_PATH", "cassette_store.db")`. If file exists, opens connection with `timeout=DB_PING_TIMEOUT`, executes `SELECT 1;`, and verifies output. If file does not exist yet (initial boot), return True if heartbeat is valid.
       - `main()`: Returns exit code 0 if both checks pass, otherwise 1 with diagnostic message to stderr.
  </action>
  <acceptance_criteria>
    - `src/scripts/healthcheck.py` exists and has zero third-party imports
    - Executable via `python -m src.scripts.healthcheck`
    - Returns 0 when `/tmp/bot_heartbeat` is fresh and SQLite DB ping succeeds
    - Returns 1 when `/tmp/bot_heartbeat` is missing or stale (>90s)
  </acceptance_criteria>
</task>

  </action>
