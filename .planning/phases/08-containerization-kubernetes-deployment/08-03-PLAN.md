# Plan 08-03: All-in-One Kubernetes Manifest & GitHub Actions CI/CD Pipeline

<objective>
Implement the single-command Kubernetes manifest (`k8s/all-in-one.yaml`) ensuring strict single-replica execution (`replicas: 1`, `strategy.type: Recreate`) with persistent volume claim and exec health probes, and establish the automated multi-arch Docker Hub build-and-push pipeline via GitHub Actions (`.github/workflows/docker-publish.yml`).
</objective>

<threat_model>
- **Threat Ref:** T-08-04 (Concurrent Multi-Pod SQLite Corruption & Split-Brain Writes)
- **STRIDE:** Tampering
- **Impact:** Multiple bot pods running simultaneously on a shared volume write concurrently to SQLite, causing fatal database lockups (`SQLITE_BUSY`) or WAL file corruption.
- **Mitigation:** Enforce `replicas: 1` and `strategy.type: Recreate` in Deployment. PersistentVolumeClaim uses `accessModes: [ReadWriteOnce]`.
- **Threat Ref:** T-08-01 (Pod Privilege Escalation)
- **STRIDE:** Elevation of Privilege
- **Impact:** Compromised container gains root privileges or mounts host root.
- **Mitigation:** Pod spec enforces `securityContext: runAsNonRoot: true, runAsUser: 10001, runAsGroup: 10001, fsGroup: 10001` with resource limits.
</threat_model>

<task id="08-03-02">
  <name>Implement GitHub Actions multi-arch Docker Hub build and push pipeline</name>
  <read_first>
    - Dockerfile
    - .planning/phases/08-containerization-kubernetes-deployment/08-CONTEXT.md
    - .planning/phases/08-containerization-kubernetes-deployment/08-RESEARCH.md
  </read_first>
  <action>
    Create `.github/workflows/docker-publish.yml`:
    - Name: `Docker Image CI/CD`
    - Trigger on:
      - `push` to branches: `[ "main" ]`
      - `push` tags: `[ "v*" ]`
      - `workflow_dispatch` (manual trigger)
    - Jobs:
      - `build-and-push`:
        - `runs-on: ubuntu-latest`
        - Steps:
          1. Checkout code: `actions/checkout@v4`
          2. Set up QEMU for multi-arch: `docker/setup-qemu-action@v3`
          3. Set up Docker Buildx: `docker/setup-buildx-action@v3`
          4. Login to Docker Hub: `docker/login-action@v3` with `username: ${{ secrets.DOCKERHUB_USERNAME }}` and `password: ${{ secrets.DOCKERHUB_TOKEN }}`
          5. Extract metadata (tags, labels): `docker/metadata-action@v5` with images `${{ secrets.DOCKERHUB_USERNAME }}/cassette-store-bot`
          6. Build and push: `docker/build-push-action@v6` with:
             - `context: .`
             - `platforms: linux/amd64,linux/arm64`
             - `push: true`
             - `tags: ${{ steps.meta.outputs.tags }}`
             - `labels: ${{ steps.meta.outputs.labels }}`
             - `cache-from: type=gha`
             - `cache-to: type=gha,mode=max`
  </action>
  <acceptance_criteria>
    - `.github/workflows/docker-publish.yml` exists and is valid YAML
    - Configures multi-arch platforms `linux/amd64,linux/arm64` via Docker Buildx
    - Uses GitHub Secrets for Docker Hub authentication
    - Builds on push to `main` and version tags
  </acceptance_criteria>
</task>
