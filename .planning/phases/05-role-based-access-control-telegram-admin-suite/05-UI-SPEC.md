# Phase 5 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Adapted for Telegram Bot UI: formatted HTML messages, visual cards, Inline Keyboard buttons, and Telegram alerts.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable (Telegram Bot UI) |
| Component library | python-telegram-bot (`InlineKeyboardMarkup`, `InlineKeyboardButton`) |
| Icon library | Standard Unicode Emoji (Telegram UI convention) |
| Font | Telegram Native Font (Sans-serif) + Monospace (`<code>`, `<pre>`) |

---

## Spacing Scale

Telegram Bot message and keyboard layout constraints (horizontal column distribution and vertical line division):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px equivalent | Single space between emoji and label text (e.g. `👑 SUPER_ADMIN`) |
| sm | 8px equivalent | Inline button column separation (PTB horizontal grid spacing) |
| md | 16px equivalent (1 newline `\n`) | Field separator within summary and status cards |
| lg | 24px equivalent (divider line) | Section dividing line `────────────────────` (20 box-drawing chars) |
| xl | 32px equivalent (2 newlines `\n\n`) | Gap between card header and body, or body and instruction footer |
| 2xl | 48px equivalent | Major navigation block separation |
| 3xl | 64px equivalent | Full screen replacement via `edit_message_text` |

Exceptions:
- Section divider rule: Exactly 20 box-drawing characters `────────────────────` (standardized across Phases 2, 3, 4, 5).
- Button grid layout: Maximum 2 columns per row for low-tech elderly readability, except compact 4-button log filters.

---

## Typography

Telegram Bot rendering engine supported HTML typography roles:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | Telegram standard (~15px) | Regular (400) | 1.4 (Telegram client default) |
| Label | Telegram bold `<b>` (~15px) | Bold (700) | 1.4 (Telegram client default) |
| Heading | Telegram header `<b>` with emoji prefix (~16px) | Bold (700) | 1.5 |
| Display | Telegram monospace `<code>` / `<pre>` (~13px) | Monospace (400) | 1.3 (Monospace pre-formatted block) |

---

## Color

Telegram UI does not support arbitrary CSS/hex styling. Colors are conveyed via standard Telegram emoji markers and native theme accenting:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Telegram Native Theme (Light/Dark surface) | Message bubble background and chat view |
| Secondary (30%) | Neutral Grey/Slate Keyboard Buttons | Standard action buttons (`[👥 Quản lý Whitelist]`, `[⬅️ Quay lại]`, `[🔄 Làm mới]`) |
| Accent (10%) | Blue / Green Indicator Emoji (`👑`, `🤖`, `✅`, `✓`) | Active model indicator, Super Admin badge, successful reachability probe |
| Destructive | Red / Warning Indicator Emoji (`⚠️`, `❌`, `⛔`) | Destructive delete buttons, role access denial alert, whitelist removal confirmation |

Accent reserved for:
- Current active LLM model marker (`[✓]`)
- Super Admin role badge (`👑`)
- Successful connection indicator (`✅`)
- Confirmation action button (`[✅ Lưu cấu hình]`)

## Screen & Interaction Specifications

### Screen 1: Admin Dashboard (`/admin`)

**Trigger:** Admin or Super Admin types `/admin` or taps `[⬅️ Quay lại]` from sub-screens.

**Message Card Format (HTML):**
```html
🛠️ <b>BẢNG ĐIỀU KHIỂN QUẢN TRỊ</b>
────────────────────
⏱️ <b>Uptime:</b> {uptime_str}
💾 <b>Database:</b> SQLite WAL (DB: {db_size_mb} MB | WAL: {wal_size_mb} MB)
🤖 <b>Model LLM:</b> <code>{active_model_id}</code> (Trạng thái: ✅ Hoạt động)
📦 <b>Đơn hôm nay:</b> {today_order_count} đơn hàng
────────────────────
Vai trò của bạn: {role_badge} <b>{user_role}</b>
```

**Inline Keyboard Layout (2 columns):**
```
[👥 Quản lý Whitelist]   [🤖 Đổi Model LLM]
[📜 Xem Logs]            [💾 Sao lưu DB]
[🔄 Làm mới]             [❌ Đóng menu]
```
*Note: For ADMIN role, `[📜 Xem Logs]` and `[💾 Sao lưu DB]` buttons are either hidden or display permission alert when tapped.*

---

### Screen 2: Whitelist Management (`adm:wl`)

**Trigger:** Tap `[👥 Quản lý Whitelist]`.

**Message Card Format (HTML):**
```html
👥 <b>QUẢN LÝ DANH SÁCH TRUY CẬP (WHITELIST)</b>
────────────────────
Tổng số tài khoản: <b>{total_users}</b>

{user_item_lines}
────────────────────
<i>Bấm vào tài khoản bên dưới để xem chi tiết / phân quyền, hoặc thêm mới:</i>
```

*Example User Line:*
- `👑 <b>Quan Tran</b> (<code>123456789</code>) - SUPER_ADMIN`
- `🛡️ <b>Nguyen Van A</b> (<code>987654321</code>) - ADMIN`
- `👤 <b>Staff 1</b> (<code>555666777</code>) - STAFF`

**Inline Keyboard Layout:**
```
[👑 Quan Tran]           [🛡️ Nguyen Van A]
[👤 Staff 1]             [➕ Thêm tài khoản]
[⬅️ Quay lại]            [❌ Đóng]
```

---

### Screen 3: User Detail & Permission Card (`adm:wl:view:{id}`)

**Trigger:** Tap a user button from Whitelist screen.

**Message Card Format (HTML):**
```html
👤 <b>THÔNG TIN TÀI KHOẢN</b>
────────────────────
🆔 <b>Telegram ID:</b> <code>{target_id}</code>
👤 <b>Tên hiển thị:</b> {name}
🛡️ <b>Vai trò hiện tại:</b> {role_badge} <b>{role}</b>
🕒 <b>Ngày cấp quyền:</b> {created_at}
────────────────────
```

**Inline Keyboard Layout (For normal user):**
```
[🛡️ Đổi vai trò: ADMIN]  [👤 Đổi: NHÂN VIÊN]
[🗑️ Xoá khỏi Whitelist]
[⬅️ Quay lại danh sách]
```
*(If target is root Super Admin, hide role change and delete buttons; display `[🛡️ Root Super Admin (Bảo vệ)]` disabled button).*

---

### Screen 4: Dynamic Model Switcher (`adm:model`)

**Trigger:** Tap `[🤖 Đổi Model LLM]`.

**Message Card Format (HTML):**
```html
🤖 <b>CẤU HÌNH MODEL LLM (9ROUTER)</b>
────────────────────
Model đang kích hoạt: <code>{active_model_id}</code>
Trạng thái gateway: ✅ Sẵn sàng

<i>Chọn model khả dụng bên dưới hoặc nhập model mới:</i>
```

**Inline Keyboard Layout:**
```
[✓ gpt-4o-mini]          [gpt-4o]
[claude-3-5-haiku]       [gemini-1.5-flash]
[✏️ Nhập tên model khác]
[⬅️ Quay lại]            [❌ Đóng]
```

**Reachability Probe Feedback (Transient state during probe):**
- Toast / Loading text: `⏳ Đang kiểm tra kết nối tới 9router với model "{candidate_model}"...`
- Success: Edit card back to Model Switcher with `✅ Đã chuyển sang model: <code>{candidate_model}</code>`.
- Failure: Edit card with Error state displaying error detail.

---

### Screen 5: System Logs Viewer (`/logs` or `adm:logs`)

**Trigger:** Super Admin types `/logs` or taps `[📜 Xem Logs]`.

**Message Card Format (HTML):**
```html
📜 <b>NHẬT KÝ HỆ THỐNG GẦN NHẤT</b>
────────────────────
<pre><code>{escaped_log_lines}</code></pre>
────────────────────
<i>Hiển thị {count} dòng gần nhất • Cập nhật lúc {timestamp}</i>
```

**Inline Keyboard Layout (1 row of filters + navigation):**
```
[25 dòng]   [50 dòng]   [⚠️ Chỉ Lỗi]   [🔄 Làm mới]
[⬅️ Menu Quản trị]      [❌ Đóng]
```
