<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Telegram Client → Bot Handler | Interactive admin callbacks and text prompts |
| Bot Server → 9router Gateway | Dynamic model test calls and candidate switching |
| Telegram Client → Log Stream | Delivery of system logs to Telegram chat |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-04 | Denial of Service | `src/services/llm_probe.py` | mitigate | Strict 5.0s timeout and 1-token prompt; on probe error or timeout, rollback/retain active model without affecting bot availability |
| T-05-05 | Elevation of Privilege | `src/bot/handlers/admin.py` | mitigate | Every admin callback query validates user role with `@require_role`; root Super Admin ID cannot be deleted or altered |
| T-05-06 | Information Disclosure | `src/bot/handlers/logs.py` | mitigate | Enforce `@require_role(UserRole.SUPER_ADMIN)`; normal `ADMIN` and `STAFF` users receive permission alert and cannot view `/logs` |
| T-05-SC | Tampering | python packages | mitigate | Zero external third-party dependencies added; all implementations rely on verified standard library and existing packages |
</threat_model>
