# Phase 7 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Adapted for Telegram Bot UI: formatted HTML messages, visual cards, Inline Keyboard buttons, CopyTextButtons, and transient states.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable (Telegram Bot UI) |
| Component library | python-telegram-bot (`InlineKeyboardMarkup`, `InlineKeyboardButton`, `CopyTextButton`) |
| Icon library | Standard Unicode Emoji (Telegram UI convention) |
| Font | Telegram Native Font (Sans-serif) + Monospace (`<code>`, `<pre>`) |

---

## Spacing Scale

Telegram Bot message and keyboard layout constraints (horizontal column distribution and vertical line division):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px equivalent | Single space between emoji and label text (e.g. `🔄 Trạng thái:`) |
| sm | 8px equivalent | Inline button column separation (PTB horizontal grid spacing) |
| md | 16px equivalent (1 newline `\n`) | Field separator within summary and status cards |
| lg | 24px equivalent (divider line) | Section dividing line `──────────────` (14 box-drawing chars per D-19) |
| xl | 32px equivalent (2 newlines `\n\n`) | Separation between modified fields in Visual Diff card, and between consecutive orders in list card per D-19 |
| 2xl | 48px equivalent | Major block transition / disambiguation choice prompts |
| 3xl | 64px equivalent | Full screen replacement via `edit_message_text` |

Exceptions:
- Section divider rule: Exactly 14 box-drawing characters `──────────────` (per D-19, shortened from 20 characters to prevent wrapping on elderly small phones or large font settings).
- Order list spacing rule: Exactly 2 newlines (`\n\n`) between consecutive orders in `render_order_list_card` to prevent cramped visual clustering on mobile screens (per D-19).
- Button layout: Maximum 2 columns per row for status options; 1 button per row for target order selection disambiguation to prevent label truncation.

## Typography

Telegram Bot rendering engine supported HTML typography roles:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | Telegram standard (~15px) | Regular (400) | 1.4 (Telegram client default) |
| Label | Telegram bold `<b>` (~15px) | Bold (700) | 1.4 (Telegram client default) |
| Heading | Telegram header `<b>` with emoji prefix (~16px) | Bold (700) | 1.5 |
| Display | Telegram monospace `<code>` / `<pre>` (~13px) | Monospace (400) | 1.3 (Monospace copy targets: SĐT, mã vận đơn, Order ID) |

## Color

Telegram UI does not support arbitrary CSS/hex styling. Colors are conveyed via standard Telegram emoji markers and native theme accenting:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Telegram Native Theme (Light/Dark surface) | Message bubble background and chat view |
| Secondary (30%) | Neutral Grey/Slate Keyboard Buttons | Standard action buttons (`[❌ Huỷ]`, `[⬅️ Quay lại thẻ đơn]`, disambiguation order buttons) |
| Accent (10%) | Green / Arrow Indicator Emoji (`✅`, `➡️`, `🔄`) | Visual diff transformation pointer (`➡️`), confirmation CTA button (`[✅ Xác nhận sửa]`), update success badge (`✅`) |
| Destructive | Red / Warning Indicator Emoji (`⚠️`, `❌`, `🚫`) | Cancellation button (`[❌ Huỷ]`), optimistic lock conflict alert (`⚠️`), terminal cancelled status (`❌ Đã huỷ đơn`) |

Accent reserved for:
- Visual diff field transition indicator (`➡️`)
- Confirmation action button (`[✅ Xác nhận sửa]`)
- Successful mutation badge (`✅ Đã cập nhật thành công đơn #{id}!`)
- Next status transition suggestion buttons (e.g. `[📦 Đã đóng gói xong]`)

## Copywriting Contract

| Element | Copy |
|---------|------|

| Back to Order Card CTA | `⬅️ Quay lại thẻ đơn` |

| Ambiguous Create vs Mutate Prompt Heading | `🤔 <b>XÁC NHẬN Ý ĐỊNH</b>` |

### 3. Error & Transient Expiry States

| Element | Copy |
|---------|------|

## Screen & Interaction Specifications

### Screen 1: Target Order Disambiguation (`ord_mut_sel`)

**Trigger:** User sends mutation intent (e.g. "sửa địa chỉ khách Tuấn") matching 2 to 5 active orders (per D-08).

**Message Card Format (HTML):**
```html
🔍 <b>CHỌN ĐƠN HÀNG CẦN SỬA</b>
<i>(Tìm thấy {count} đơn hàng của '{keyword}')</i>
──────────────
Bác bấm chọn đúng đơn cần sửa bên dưới nhé:
```

**Inline Keyboard Layout (1 button per row):**
```
[📦 Đơn #12 - Nam - 250.000 đ - Chờ làm]
[📦 Đơn #15 - Nam - 400.000 đ - Đang làm]
[❌ Huỷ]
```
*Note: Tapping a choice button immediately applies the extracted delta and transitions to Screen 2 (per D-10).*

---

### Screen 2: Visual Diff Confirmation Card (`ord_mut_cf` / `ord_mut_ca`)

**Trigger:** System resolves target order and extracts field delta (per D-11, MUT-04).

**Message Card Format (HTML):**
```html
📝 <b>XÁC NHẬN SỬA ĐƠN HÀNG #{order_id}</b>
👤 <b>Khách:</b> {customer_name}
──────────────
<b>Các nội dung thay đổi:</b>

{diff_lines}
──────────────
Bác kiểm tra lại thông tin rồi bấm nút bên dưới nhé (hết hạn sau 120s):
```

**Field Diff Formatting Rules:**
- **Status:** `🔄 <b>Trạng thái:</b> {old_status_label} ➡️ <b>{new_status_label}</b>`
- **Phone:** `📞 <b>SĐT:</b> <code>{old_phone}</code> ➡️ <code>{new_phone}</code>`
- **Address:** `📍 <b>Địa chỉ:</b>\n   [Cũ]: {old_address}\n   ➡️ [Mới]: <b>{new_address}</b>`
- **COD Amount:** `💵 <b>Tiền COD:</b> {old_cod_fmt} ➡️ <b>{new_cod_fmt}</b>`
- **Total Amount:** `💰 <b>Tổng tiền:</b> {old_total_fmt} ➡️ <b>{new_total_fmt}</b>`
- **Tracking Code:** `🚚 <b>Mã vận đơn:</b> <code>{old_tracking}</code> ➡️ <code>{new_tracking}</code>`
- **Items:** `📼 <b>Băng:</b> {old_items} ➡️ <b>{new_items}</b>`
- **Notes:** `📝 <b>Ghi chú mới:</b> {new_notes}`

**Inline Keyboard Layout (1 row of 2 buttons):**
```
[✅ Xác nhận sửa]   [❌ Huỷ]
```

**Timeout Behavior (120s TTL per D-12):**
- Upon timeout or user tap on `[❌ Huỷ]`, edit message in-place:
  - Header: `❌ Đã huỷ yêu cầu sửa đơn` or `⏰ Đã hết hạn 120s`
  - Body: Notice that order was preserved without changes
  - `reply_markup`: Removed completely (`None`) to prevent duplicate taps.

### Screen 3: Next Status Disambiguation (`ord_mut_st`)

**Trigger:** User specifies intent to change status (e.g. "chuyển trạng thái đơn 12") but does not name target status (per MUT-05, D-13).

**Message Card Format (HTML):**
```html
🔄 <b>CHỌN TRẠNG THÁI TIẾP THEO</b>
📦 <b>Đơn hàng #{order_id}</b> - {customer_name}
Hiện tại: <b>{current_status_label}</b>
──────────────
Bác muốn chuyển đơn này sang bước nào ạ:
```

**Inline Keyboard Layout (Contextual suggestions based on lifecycle, 1 or 2 per row):**
*(Example for order in `DANG_LAM`)*
```
[📦 Đã đóng gói xong]
[📑 Đã tạo đơn ship]
[❌ Huỷ đơn này]
[⬅️ Quay lại thẻ đơn]
```
*Note: Selecting a status immediately renders the Visual Diff Card (Screen 2) for final confirmation.*

---

### Screen 4: Post-Mutation Success Card (Edit in-place)

**Trigger:** User taps `[✅ Xác nhận sửa]`, optimistic lock succeeds (per D-14).

**Message Card Format (HTML):**
```html
✅ <b>ĐÃ CẬP NHẬT THÀNH CÔNG ĐƠN #{order_id}!</b>
──────────────
📦 <b>CHI TIẾT ĐƠN HÀNG #{order_id}</b>
Trạng thái: <b>{status_label}</b>
──────────────
👤 <b>Khách:</b> {customer_name}
📞 <b>SĐT:</b> <code>{customer_phone}</code> <i>(chạm để copy)</i>
📍 <b>Địa chỉ:</b> <code>{shipping_address}</code>
📼 <b>Băng:</b> {items_text}
💰 <b>Tổng tiền:</b> {total_amount_fmt}
💵 <b>Tiền COD thu:</b> {cod_amount_fmt}
🚚 <b>Mã vận đơn:</b> {tracking_code_str}
📷 <b>Ảnh đính kèm:</b> {photo_count_str}
🕒 <b>Thời gian:</b> {created_time_str} (bởi {creator_name})
──────────────
```
*Note: Message replaces the diff card completely. Reply markup displays standard order detail actions (`build_order_detail_keyboard`).*

---

### Screen 5: Optimistic Concurrency Conflict Notice

**Trigger:** User taps `[✅ Xác nhận sửa]`, but SQLite returns `rowcount == 0` because `updated_at` changed within 120s (per D-17, D-18).

**Message Card Format (HTML):**
```html
⚠️ <b>XUNG ĐỘT SỬA ĐƠN HÀNG #{order_id}!</b>
──────────────
Đơn hàng này vừa được <b>{modifier_name}</b> sửa lúc <b>{modified_time}</b>:
{changes_summary}

Thao tác sửa của bác đã tạm dừng để tránh đè dữ liệu. Dưới đây là thông tin mới nhất:
──────────────
📦 <b>CHI TIẾT ĐƠN HÀNG #{order_id}</b>
Trạng thái: <b>{fresh_status_label}</b>
👤 <b>Khách:</b> {fresh_customer_name}
📞 <b>SĐT:</b> <code>{fresh_customer_phone}</code>
📍 <b>Địa chỉ:</b> <code>{fresh_shipping_address}</code>
💰 <b>Tổng tiền:</b> {fresh_total_fmt} | 💵 <b>COD:</b> {fresh_cod_fmt}
```
*Reply markup: Standard `build_order_detail_keyboard(fresh_order)`.*
