<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Telegram Client → Mutation Callback Handler | Untrusted callback data and parameters (`ord_mut_*`) sent from user clients |
| In-Memory Cache → Mutation Execution | User draft states stored in `context.user_data` with 120s TTL |
| Concurrency Gate → SQLite Storage | Multiple concurrent admins updating the same order record |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-04 | Tampering / Race Condition | `src/db/orders.py::mutate_order_with_lock` | mitigate | Optimistic concurrency check `WHERE id = ? AND updated_at = ?` prevents overwriting changes made by another admin |
| T-07-05 | Repudiation / Audit Evasion | `src/db/orders.py::mutate_order_with_lock` | mitigate | Every successful mutation logs an immutable record to `order_history` with `user_id`, `user_name`, timestamp, and serialized JSON diff |
| T-07-06 | Denial of Service / Memory Bloat | `context.user_data["pending_mutations"]` | mitigate | Strict 120s TTL enforced on every callback; expired drafts are pruned and message buttons cleared |
| T-07-07 | Information Disclosure / XSS | `src/bot/keyboards.py::render_mutation_diff_card` | mitigate | All strings (customer name, address, notes, items) escaped with `html.escape()` before insertion into Telegram HTML message |
| T-07-SC | Tampering | npm/pip installs | mitigate | Zero external package installs; uses verified existing standard stack |
</threat_model>
